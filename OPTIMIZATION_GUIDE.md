# Руководство по оптимизации создания векторной базы

## Обзор оптимизаций

Этот документ описывает настройки для оптимизации скорости и точности создания векторной базы данных.

## Переменные окружения для оптимизации

### Скорость vs Точность

#### 1. Модель эмбеддингов

```bash
# Для максимальной скорости (быстрее в 3-5 раз, но менее точная)
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIMENSIONS=512

# Для максимальной точности (рекомендуется)
EMBEDDING_MODEL=text-embedding-3-large
EMBEDDING_DIMENSIONS=1536

# Баланс (по умолчанию)
EMBEDDING_MODEL=text-embedding-3-large
EMBEDDING_DIMENSIONS=1536
```

**Сравнение:**
- `text-embedding-3-small`: ~$0.02 за 1M токенов, быстрее, размерность 512/1536
- `text-embedding-3-large`: ~$0.13 за 1M токенов, медленнее, размерность 3072/1536

#### 2. Размер чанков

```bash
# Меньшие чанки = больше точность, но больше запросов
CHUNK_SIZE=800      # Быстрее, но может потерять контекст
CHUNK_SIZE=1200     # Баланс (рекомендуется)
CHUNK_SIZE=1500     # Медленнее, но лучше контекст

# Перекрытие чанков (для лучшего контекста)
CHUNK_OVERLAP=200   # Минимальное (быстрее)
CHUNK_OVERLAP=300   # Баланс (рекомендуется, 25% overlap)
CHUNK_OVERLAP=400   # Максимальное (медленнее, но лучше контекст)
```

**Рекомендации:**
- Для технических документов: `CHUNK_SIZE=1200`, `CHUNK_OVERLAP=300`
- Для коротких документов: `CHUNK_SIZE=800`, `CHUNK_OVERLAP=200`
- Для длинных документов: `CHUNK_SIZE=1500`, `CHUNK_OVERLAP=400`

#### 3. Размер батчей

```bash
# Автоматический расчет (рекомендуется)
# Система сама рассчитает оптимальный размер на основе размера чанков

# Ручная настройка (если нужно)
EMBEDDING_BATCH_SIZE=500   # Консервативный (безопасный)
EMBEDDING_BATCH_SIZE=800   # Оптимальный (рекомендуется)
EMBEDDING_BATCH_SIZE=1000  # Агрессивный (может вызвать ошибки)
```

**Формула расчета:**
- Средний размер чанка / 4 = токены на чанк
- 250000 / токены на чанк = безопасный размер батча

## Примеры конфигураций

### Конфигурация для скорости

```bash
# .env файл
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIMENSIONS=512
CHUNK_SIZE=1000
CHUNK_OVERLAP=200
EMBEDDING_BATCH_SIZE=1000
```

**Ожидаемое время:** ~30-40% от времени с large моделью
**Точность:** ~85-90% от large модели

### Конфигурация для точности

```bash
# .env файл
EMBEDDING_MODEL=text-embedding-3-large
EMBEDDING_DIMENSIONS=1536
CHUNK_SIZE=1500
CHUNK_OVERLAP=400
EMBEDDING_BATCH_SIZE=600
```

**Ожидаемое время:** Полное время
**Точность:** Максимальная

### Сбалансированная конфигурация (рекомендуется)

```bash
# .env файл
EMBEDDING_MODEL=text-embedding-3-large
EMBEDDING_DIMENSIONS=1536
CHUNK_SIZE=1200
CHUNK_OVERLAP=300
EMBEDDING_BATCH_SIZE=800
```

**Ожидаемое время:** ~70-80% от максимального
**Точность:** ~95-98% от максимальной

## Дополнительные оптимизации

### 1. Параллельная обработка PDF

Параллельная обработка PDF файлов уже реализована в коде. Для больших объемов это может ускорить процесс на 2-3x.

### 2. Кэширование эмбеддингов

Для повторных запусков база не пересоздается, если она уже существует. Это экономит время и деньги.

### 3. Инкрементальное обновление

Можно добавить логику для обновления только новых/измененных документов (требует доработки кода).

## Мониторинг производительности

Система автоматически выводит:
- Время обработки каждого этапа
- Количество обработанных чанков
- Размер базы данных
- Процент прогресса

## Рекомендации по использованию

1. **Первое создание базы:** Используйте сбалансированную конфигурацию
2. **Тестирование:** Используйте конфигурацию для скорости
3. **Продакшн:** Используйте конфигурацию для точности
4. **Большие объемы:** Уменьшите `CHUNK_SIZE` и увеличьте `EMBEDDING_BATCH_SIZE`

## Оценка времени и стоимости

Для 30,000 чанков (примерно 167 PDF файлов):

### Скорость (small модель):
- Время: ~15-20 минут
- Стоимость: ~$0.50-0.75

### Баланс (large модель, оптимизированные батчи):
- Время: ~45-60 минут
- Стоимость: ~$3-4

### Точность (large модель, большие чанки):
- Время: ~60-90 минут
- Стоимость: ~$4-6

## Устранение проблем

### Ошибка "max_tokens_per_request"
- Уменьшите `EMBEDDING_BATCH_SIZE`
- Уменьшите `CHUNK_SIZE`

### Медленная обработка
- Используйте `text-embedding-3-small`
- Увеличьте `EMBEDDING_BATCH_SIZE` (с осторожностью)
- Уменьшите `CHUNK_OVERLAP`

### Низкая точность поиска
- Используйте `text-embedding-3-large`
- Увеличьте `CHUNK_SIZE`
- Увеличьте `CHUNK_OVERLAP`
